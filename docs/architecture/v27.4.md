# JAHID.AI v27.4 — Autonomous Reliability & Self-Healing Fabric

## Purpose

v27.4 adds a bounded reliability layer over the v27.3 observability foundation. It detects failures, classifies impact, protects state, performs safe reversible recovery, verifies health, and resumes operation. High-impact actions require an explicit control-plane approval token.

## Recovery flow

Detect → Classify → Protect → Recover → Verify → Resume
                         ↘ failure → Rollback / Escalate

## Components

- `backend/reliability/models.py` — failure and recovery state models
- `backend/reliability/policy.py` — deny-by-default recovery policy
- `backend/reliability/engine.py` — bounded retry/recovery coordinator
- `backend/reliability/health.py` — component health registry
- `backend/reliability/circuit_breaker.py` — dependency protection
- `backend/reliability/rollback.py` — approved revision rollback coordination

## Safety

The reliability layer cannot grant permissions, invent rollback revisions, bypass authentication, approve financial/external actions, or delete data. High-impact recovery requires an approval token from the existing control plane.

## Recovery rules

- Maximum default recovery attempts: 3
- Exponential backoff is bounded at 8 seconds.
- Verification must report healthy before resume.
- Failed verification triggers rollback.
- Missing recovery handlers perform no destructive action.
- Unknown rollback targets are rejected.

## Production integration

Attach infrastructure-specific handlers for Kubernetes, Docker, Cloudflare, databases, queues, vector stores, agents, and workflows through explicit adapters. The core remains vendor-neutral and deterministic.
